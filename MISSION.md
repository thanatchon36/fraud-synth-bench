# MISSION: Reproducible Fraud Analytics Research on Synthetic Data

You are an autonomous research engineer. Your job is to run a complete, publishable-quality research project on **fraud analytics** end-to-end — literature review → research questions → synthetic data → experiments (classic vs. modern models) → paper → public GitHub repo — with every result reproducible by a stranger running one command.

Work through all phases without waiting for me. Make reasonable decisions yourself, record each one in `docs/DECISIONS.md` (what, why, alternatives rejected), and keep going. Only stop if something is truly blocked (e.g. a credential I must supply).

---

## 0. Hard constraints

- **No real data. Ever.** All datasets are generated by code in this repo. Do not download Kaggle/IEEE-CIS/PaySim/etc. You may *read* papers that use them to learn what real fraud looks like, then encode those patterns into a generator.
- **Reproducibility is the deliverable.** Fixed seeds, pinned dependencies, deterministic generators, `make reproduce` rebuilds every table and figure in the paper from scratch.
- **Honest science.** Report negative results. Never tune on the test set. Use ≥5 seeds and report mean ± std with confidence intervals. If a "new" model loses to logistic regression, say so.
- **Compute target: MacBook Air M4, 16 GB unified memory, no CUDA, fanless.** Design every experiment for this machine:
  - PyTorch device selection: `mps` if available, else `cpu`. Never hard-code `cuda`. Wrap MPS use so any unsupported op falls back to CPU rather than crashing.
  - Memory: peak RSS of any single process ≤ 10 GB. Use Polars or pandas with categorical/Arrow dtypes; stream from parquet; never hold more than one dataset preset in memory at once.
  - Two generator presets: `small` (≈ 200k transactions, 20k accounts, 30 days) for the full experiment suite, and `full` (≈ 2M transactions) that is documented and tested but *not* required for the paper. The paper reports `small` unless a specific RQ needs more rows, and the preset is recorded in every manifest and table caption.
  - Graph models: PyTorch Geometric has incomplete MPS support — run GNNs on CPU, keep graphs ≤ 200k nodes / 1M edges, and use mini-batch neighbour sampling.
  - TabPFN: CPU-only, cap training rows at ~10k via stratified temporal subsampling; log the subsampling in `DECISIONS.md` and treat "modern model needs subsampling, GBDT doesn't" as a reportable finding for RQ1.
  - Prefer LightGBM over XGBoost as the primary GBDT (lighter on ARM). Optuna budget ≤ 30 trials per model, early-stopped.
  - Ollama (optional LLM features): quantized model ≤ 4B parameters, outputs cached to disk and seeded; skip entirely if it pushes the suite past budget.
  - Time budget: full suite ≤ 90 minutes wall-clock to avoid thermal throttling; `make quick` smoke run ≤ 5 minutes. Run long targets via `caffeinate -i` so the Mac doesn't sleep. Log per-stage wall time to `results/timing.json`.
- **License:** Apache-2.0. Public repo. No secrets, no PII, no vendor-specific data.
- Python 3.11+, `uv` for env, `pytest` for tests, `ruff` for lint, type hints throughout. All dependencies must have arm64 macOS wheels; isolate anything CUDA-only behind an optional extra that is never required for `make reproduce`.

## 1. Phase 1 — Literature review (`docs/literature/`)

1. Search arXiv / Semantic Scholar / Google Scholar for fraud detection work, 2015 → today. Cover at least these threads:
   - Classical: logistic regression, random forest, gradient boosting (XGBoost/LightGBM/CatBoost) on tabular transactions
   - Anomaly / unsupervised: Isolation Forest, One-Class SVM, autoencoders, VAEs
   - Sequence: LSTM/GRU over per-account transaction histories, temporal CNNs
   - Graph: GNNs (GraphSAGE, GAT, CARE-GNN, PC-GNN) on transaction / account graphs
   - Foundation-model era: TabPFN, tabular transformers (FT-Transformer, SAINT), LLM-assisted feature engineering, LLM-as-judge for anomaly explanation
   - Operational: concept drift, label delay, cost-sensitive learning, extreme class imbalance (<0.5% positives), feedback loops from investigator decisions
   - Synthetic fraud data generation: PaySim-style agent simulators, CTGAN/TVAE, rule-based injection
2. Produce `docs/literature/REVIEW.md`: ~20–40 papers, each with 3–5 line summary, dataset used, metrics, key claim, and **what gap it leaves open**. Add a BibTeX file `docs/literature/refs.bib`.
3. End the review with a **gap analysis table** — which (model family × data regime × evaluation condition) combinations are under-tested. These gaps become the research questions.

---

## 2. Phase 2 — Research questions (`docs/RESEARCH_QUESTIONS.md`)

Pick **3–5 falsifiable research questions** from the gap analysis. Each must have: a hypothesis, the experiment that would refute it, the metric, and the decision threshold. Defaults if the literature review doesn't point elsewhere:

- **RQ1 (Old vs. new):** Under extreme imbalance (0.1–1% fraud), do modern tabular models (TabPFN, FT-Transformer) beat tuned gradient boosting on AUPRC, or does the advantage vanish once GBDT is tuned?
- **RQ2 (Concept drift):** When fraudsters adapt mid-stream (pattern shift at t = 60% of timeline), which model family degrades least, and how much does periodic retraining recover?
- **RQ3 (Graph vs. tabular):** Does collusion/ring fraud (shared devices, mule accounts) give GNNs a measurable edge over tabular models fed hand-crafted graph features (degree, PageRank, shared-entity counts)?
- **RQ4 (Label delay):** How much does realistic label latency (fraud confirmed 7–30 days after the event) hurt each model family, and does semi-supervised / anomaly pretraining mitigate it?
- **RQ5 (Cost):** Under a cost matrix (false-negative cost ≫ false-positive cost, investigation capacity = top-k alerts/day), which model maximizes recovered loss per investigator-hour?

## 3. Phase 3 — Synthetic data generator (`src/fraudlab/synth/`)

Build a **documented, parameterized, seeded** generator — this is a reusable library, not a script.

- Agent-based simulation: customers, merchants, devices, accounts; legitimate behaviour drawn from realistic distributions (amount log-normal, hour-of-day, merchant category mix, inter-arrival times).
- Fraud **scenario injectors** as pluggable classes, each with its own docstring citing the paper/pattern it imitates:
  - card-testing bursts, account takeover, velocity abuse, mule networks / money-laundering rings, merchant collusion, synthetic identity, friendly fraud / chargeback abuse, bust-out
- Knobs: fraud rate, n_accounts, n_days, drift schedule (which scenarios appear when), label-delay distribution, noise level.
- Outputs: `transactions.parquet`, `accounts.parquet`, `edges.parquet` (graph), `labels.parquet` (true label, observed label, label_available_at), plus a `manifest.json` with generator version, params, seed, and content hash.
- Validation: `tests/test_synth.py` checks determinism (same seed → same hash), fraud-rate tolerance, and that each injector produces its signature statistics. Include a `docs/data/DATA_CARD.md` (datasheet-style) describing distributions, known limitations, and how it differs from real data.

## 4. Phase 4 — Experiments (`src/fraudlab/models/`, `experiments/`)

- A single `Experiment` config (YAML) = dataset params × model × eval protocol × seeds. All runs logged to `results/runs/*.jsonl` (no external tracking service required; MLflow optional, local only).
- **Models (implement a common `fit / predict_proba / explain` interface):**
  - Baselines: LogisticRegression, RandomForest, XGBoost/LightGBM (with proper tuning via Optuna, budgeted), IsolationForest, Autoencoder
  - Sequence: GRU over account history
  - Graph: GraphSAGE (PyTorch Geometric), plus "tabular + graph features" ablation
  - Modern tabular: TabPFN (if licence/size permits), FT-Transformer
  - Optional: LLM feature extractor via a local Ollama model — only if it runs offline and is seeded/cached; otherwise document as future work
- **Eval protocol:** strict temporal train/valid/test split (never random), AUPRC as primary, plus ROC-AUC, recall@k, precision@k, F1 at tuned threshold, cost-weighted loss, calibration (ECE), and latency per 1k predictions. Report mean ± 95% CI over ≥5 seeds. Statistical test (paired, across seeds) for any claimed difference.
- **Drift experiments:** rolling-window retrain vs. static; plot metric over time.
- Everything orchestrated by `make experiments`; each figure/table in the paper is produced by exactly one script in `experiments/` and written to `results/`.

## 5. Phase 5 — Paper (`paper/`)

- Write `paper/paper.md` (and build `paper/paper.pdf` via pandoc + LaTeX template; `make paper`). Structure: Abstract, Introduction, Related Work (from Phase 1), Synthetic Data Framework, Experimental Setup, Results (one subsection per RQ), Threats to Validity (especially: synthetic ≠ real), Reproducibility Statement, Conclusion, References.
- Every number in the paper must be generated by `make reproduce` — no hand-typed numbers. Use a `results/summary.json` → template injection pipeline.
- Tone: concise, neutral, no hype. State clearly where modern models did *not* help.
- Also produce a 1-page `docs/EXEC_SUMMARY.md` translating findings into business terms: expected loss reduction, investigator workload, operational risks (drift, label delay), and a recommendation.

- When you must choose between "more models" and "cleaner evidence for the RQs", choose cleaner evidence.
- Keep a `docs/FUTURE_WORK.md` for everything you wanted to do but cut.
